# ATLAS Test Targets

Test targets define the LLM provider, model, and search parameters for ATLAS queries. Each target creates a complete question-answering pipeline configuration.

## Overview

Test targets are stored as `.txt` files in `backend/targets/`. They can be:
- **Generated by the wizard** during the corpus build target configuration step
- **Created manually** for advanced use cases or scripted pipelines

The active target is set via the `TEST_TARGET` environment variable in `config/.env.{environment}`.

## Target File Format

Each target file is a simple key-value configuration:

```
# Target configuration
# Generated by Corpus Wizard or created manually

LLM_PROVIDER=anthropic
LLM_MODEL=claude-3-5-haiku-20241022
SEARCH_K=20
SEARCH_TYPE=similarity
SCORE_THRESHOLD=0.7
TEMPERATURE=0.7
MAX_TOKENS=4096
```

### Required Fields

| Field | Description | Example |
|-------|-------------|---------|
| `LLM_PROVIDER` | LLM provider identifier | `anthropic`, `openai`, `google`, `bedrock`, `ollama` |
| `LLM_MODEL` | Model identifier | `claude-3-5-haiku-20241022`, `gpt-4o`, `gemini-1.5-pro` |
| `SEARCH_K` | Number of documents to retrieve | `20` |
| `SEARCH_TYPE` | Search strategy | `similarity`, `mmr` |

### Optional Fields

| Field | Description | Default |
|-------|-------------|---------|
| `SCORE_THRESHOLD` | Minimum relevance score | `0.7` |
| `TEMPERATURE` | LLM temperature | `0.7` |
| `MAX_TOKENS` | Maximum response tokens | `4096` |

## File Naming Convention

Target files follow the pattern: `k{search_k}_{provider_model}.txt`

Examples:
- `k20_claude_3_5_haiku_202.txt`
- `k20_gpt_4o.txt`
- `k15_gemini_pro.txt`

## Creating Targets

### Via Wizard (Recommended)

The corpus wizard includes a target configuration step:
1. During corpus build, configure the LLM provider and model
2. Set search parameters (search_k, search_type, score_threshold)
3. The wizard generates the target file and updates `TEST_TARGET` in `.env`

### Manual Creation

Create a `.txt` file in `backend/targets/`:

```bash
cat > backend/targets/k20_claude_sonnet.txt << 'EOF'
LLM_PROVIDER=anthropic
LLM_MODEL=claude-sonnet-4-20250514
SEARCH_K=20
SEARCH_TYPE=similarity
SCORE_THRESHOLD=0.7
TEMPERATURE=0.7
MAX_TOKENS=4096
EOF
```

Then update the environment file:
```bash
# In config/.env.development
TEST_TARGET=k20_claude_sonnet
```

## Target Selection

The active target is determined by:
1. `TEST_TARGET` environment variable in `.env.{environment}`
2. The target name maps to `backend/targets/{name}.txt`
3. Config module loads the target file and merges settings

## Supported Providers

### Anthropic
```
LLM_PROVIDER=anthropic
LLM_MODEL=claude-3-5-haiku-20241022
```
Supports prompt caching for reduced latency and cost.

### OpenAI
```
LLM_PROVIDER=openai
LLM_MODEL=gpt-4o
```

### Google
```
LLM_PROVIDER=google
LLM_MODEL=gemini-1.5-pro
```

### AWS Bedrock
```
LLM_PROVIDER=bedrock
LLM_MODEL=anthropic.claude-3-5-haiku-20241022-v1:0
```
Requires AWS credentials in `.env` files.

### Ollama (Local)
```
LLM_PROVIDER=ollama
LLM_MODEL=llama3.1
```
Requires Ollama running locally. Configure `OLLAMA_ENDPOINT` in `.env`.

## Relationship to Configuration

Test targets work alongside other configuration sources:

| Source | What it provides |
|--------|-----------------|
| Target file | LLM provider, model, search parameters |
| `corpus_active.json` | Retriever module, collection, embedding model, filters |
| `.env` file | API keys, Redis, telemetry, authentication |

The target file does **not** contain corpus-specific settings (embedding model, collection name, filters). Those are managed by the wizard and stored in `corpus_active.json`.

## Telemetry

The target name is included in telemetry spans as `composite_target`, enabling performance comparison across different LLM configurations. The format combines search_k, model name, and collection name.
