# v0.4.0 — Inter-rater study integrity (DRAFT)

This release prepares ATLAS for the inter-rater reliability focus group study
(20 paid reviewers × 20 ratings each, 100 prompts) and makes the study's
statistical guarantees enforceable rather than assumed.

**Note on citation:** v0.3.0's release notes describe a 15-reviewer, 3-ratings
design. That design has changed, so v0.3.0 is no longer an accurate description
of the study. Cite the version you actually ran.

## Required configuration changes

This release fails fast on incomplete configuration instead of degrading
silently. The backend will not start, or will refuse allocations, if these are
missing. Set them before deploying:

```bash
INTER_RATER_MAX_RATINGS=4                       # was 3
INTER_RATER_REVIEWERS=20                        # new, required
INTER_RATER_SESSIONS_PER_USER=20
INTER_RATER_POOL_MANIFEST=data/seed_pool.json   # new, required in focus-group mode
INTER_RATER_PROJECT=<must equal PHOENIX_PROJECT_NAME>
```

`INTER_RATER_REVIEWERS` is part of the capacity equation, not spare capacity:
balanced allocation is active only while
`REVIEWERS × SESSIONS_PER_USER = pool × MAX_RATINGS`. Padding it silently
disables balanced allocation.

Also bump `ATLAS_VERSION` before seeding — it is recorded as a top-level Phoenix
span attribute, so it stamps the study data with the code version.

## Highlights since v0.3.0

- **Study design retuned for 20 reviewers.** `100 × 4 = 400 = 20 × 20`, a
  saturated 1:1 design giving every prompt exactly 4 independent ratings. At the
  previous `MAX_RATINGS=3`, capacity was 300 against 400 demanded and no reviewer
  could complete their contracted 20.
- **Reviewer assignment now spreads across the pool.** The previous contiguous
  block assignment gave every prompt the right number of ratings but split the
  cohort into 5 disjoint groups of 4 rating identical prompts, leaving 160 of 190
  reviewer pairs sharing nothing. That made rater severity inseparable from
  prompt block and turned one study of 100 prompts into five unrelated studies of
  20. Quota-greedy assignment with a hash tiebreak keeps exact saturation while
  bringing mean pair overlap to the theoretical optimum.
- **Atomic submission gate.** A Redis per-span lock serialises the
  count-and-write across all workers, so concurrent reviewers cannot push a
  prompt past `MAX_RATINGS`. Fails closed: a rating that cannot be verified
  against the cap is rejected rather than written.
- **Explicit seeded study pool.** `make seed` records the prompts it created in
  `data/seed_pool.json`, and allocation is restricted to exactly those. Organic
  traffic in the same Phoenix project cannot enter the study, every reviewer sees
  an identical pool, and reviewer cohort slots key on a fingerprint that cannot
  move mid-run.
- **Per-reviewer quota scoped to the active pool.** Ratings from a replaced pool
  in the same project no longer consume a new cohort's quota, and allocation,
  stats and the sessions API share one completion scope so the dashboard cannot
  declare completion early.
- **Fail-fast configuration.** Required study settings with no embedded defaults;
  `INTER_RATER_PROJECT`/`PHOENIX_PROJECT_NAME` mismatch rejected at startup (it
  previously surfaced zero sessions with no error); focus-group mode requires a
  readable study pool; a pool that no longer satisfies the capacity equation
  raises instead of reverting to unbalanced ranking.
- **Evaluation rubric.** Six Likert scales — corpus fidelity, citation quality,
  relevance, coherence, uncertainty, historical contextualisation — with
  per-scale rationales required for extreme ratings, and a global fault
  rationale. Superseded fields are retained on the model and Phoenix write path
  for backward compatibility with previously collected data.
- **Documentation.** `docs/inter_rater.md` records the allocation algorithm and
  why it spreads rather than blocks, the study-pool guarantees, the
  configured/unset manifest semantics, pilot sizing constraints, and reviewer
  briefing guidance for the fail-closed retry behaviour.
- **Tests.** Allocation coverage simulated against the real allocator (arrival
  patterns, pair-overlap balance, capacity traps), study-pool manifest handling,
  submission gate behaviour, and allocation wiring.
